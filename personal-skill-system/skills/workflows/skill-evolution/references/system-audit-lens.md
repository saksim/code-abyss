# System Audit Lens

Audit the bundle as one governed portfolio, not as unrelated skill folders.

Use six layers:

1. portfolio intent
2. trigger surface
3. route quality
4. depth quality
5. execution quality
6. governance quality

## Portfolio intent

Check:

- whether the change is really current-skill hardening or future-skill admission work
- whether missing capability demand is visible in opportunity or admission flow instead of buried in notes
- whether a proposed new skill is actually cleaner than deepening an existing route

## Trigger surface

Check:

- whether each skill has a crisp job
- whether descriptions trigger on real user phrasing
- whether names and aliases are stable
- whether adjacent skills are separated by intent, not only by topic

## Route quality

Check:

- whether the root router can distinguish knowledge, execution, validation, release, and self-system work
- whether conflicts are resolved by stable rules
- whether auto-chains follow risk and scope
- whether generated route metadata covers the actual live skill set

## Depth quality

Check:

- whether `SKILL.md` stays concise
- whether rich detail lives in references
- whether references are one hop away and loadable on demand
- whether expert depth is normalized instead of duplicated across siblings

## Execution quality

Check:

- whether tools do deterministic work
- whether workflows have a real chain, not just slogans
- whether guards consume tool output instead of acting as empty warnings
- whether runtime-proof and host-smoke claims still match reality

## Governance quality

Check:

- schema coverage
- registry coverage
- route regression
- stale review rhythm
- collision detection
- portable copy semantics
- clean lifecycle state for add, promote, merge, archive, and delete operations
